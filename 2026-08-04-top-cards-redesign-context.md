# Context: Redesign of Top Cards (Dashboard)

**Status:** Draft — обсуждение, имплементация отложена
**Date:** 2026-08-04
**Scope:** Верхние карточки (top row) на `dashboard.html`
**Out of scope:** нижние 2x3 KPI, weekly chart, 24H stream, шкалы, остальная страница

## 1. Background

Текущая верхняя полоса — 3 разнородные карточки в одном ряду:

| Карточка          | Содержимое                                                                                                                            | Плотность  |
| ----------------- | ------------------------------------------------------------------------------------------------------------------------------------- | ---------- |
| Текущий момент    | Live-поток, метаданные (LIVE/MSK/UTC+3/5MIN POLL/INPUT+OUTPUT), 153.5K TOK, sparkline, 5-мин polling, MSK 15:00-15:59, +8% к среднему | Плотная    |
| System Health     | Uptime 94% (30d), OK badge, "2 события < 1M"                                                                                          | Полупустая |
| Дельта к прогнозу | +12% vs FCST, "vs скользящее среднее · 7d", WARN/14:00 SPIKE badge, sparkline                                                         | Полупустая |

**Что не так:**

- 3 карточки про разные concerns (tokens / operational health / forecast) — глаз не знает, какая главная.
- Дисбаланс плотности: левая набита, средняя и правая пустые на ~60%.
- Sparkline в live и forecast на разных шкалах — сравнивать бессмысленно.
- System Health занимает столько же места, сколько live-поток на 153.5K TOK.

## 2. Reference (целевой паттерн)

Скриншот 2: общий header (`Расход токенов runtime · 5-мин · Europe/Moscow UTC+3`) + 4 равные time-window карточки в одном ряду (`Текущий момент 80.8K / Сегодня 807.4K / Рабочее время 608.3K / Активность 5/15`).

Паттерн: **scannable vertical scan, единый язык, одна иерархия**.

## 3. Новые требования (от владельца, 2026-08-04)

Владелец добавил 3 метрики, которые **обязаны остаться** в редизайне:

1. **Активность сессии** — текущее состояние / count активных сессий
2. **Запросы** — count запросов
3. **Среднее число запросов** — antifraud-метрика, не позволяет раздуть сессию (когда при тех же токенах скрипт генерирует тысячи пустых микро-запросов)

Эти три — **не optional**, дизайн должен их вместить без смещения фокуса.

## 4. Варианты (раунд 1, от TL)

### A. Time-window grid (по референсу)

4 равные карточки: `Текущий час · Сегодня · Рабочее окно · Прогноз EOD`. System Health → chip в header.

- ✅ скан за 2 сек, единый язык
- ⚠️ не вмещает 3 antifraud-метрики

### B. 1 hero + 3 supporting

Hero «Текущий момент» (как сейчас, 50% ширины) + 3 равные справа: `Сегодня · Рабочее окно · Прогноз`. Health → chip.

- ✅ один фокус
- ⚠️ не вмещает antifraud

### C. Нормализация текущих 3

Добить System Health (7d uptime sparkline) и Forecast (band верх/низ) контентом.

- ✅ меньше работы
- ⚠️ не лечит главное (3 разных concerns в одном ряду), не вмещает antifraud

**Все 3 варианта не вмещают 3 новые antifraud-метрики** — нужен второй раунд.

## 5. Предложение дизайнера (раунд 2)

3 блока по concerns:

### Block 1: Real-time

- `Текущий момент: 127.0K`
- `Активность сессии: 4.2K`
- `System Health: OK`

### Block 2: Aggregation + Antifraud

- `Сегодня: 853.6K`
- `Рабочее время: 654.5K`
- `Среднее число запросов: 1.5K`

### Block 3: Trends

- `Дельта к прогнозу: +12%` (с sparkline)

## 6. Критика предложения дизайнера (от TL)

### Что хорошо

- 3 блока по concerns (realtime / aggregation / trend) — логичное разделение.
- Среднее число запросов рядом с токенами — правильное соседство для antifraud.
- Нейминг `АКТИВНОСТЬ СЕССИИ` вместо просто `АКТИВНОСТЬ` — снижает путаницу.

### Что сломано

1. **7 карточек** — перебор. Reference показывал 4. Глаз устаёт, паттерн time-window размывается.
2. **Block 1 неоднородный.** "Текущий момент" (tokens) + "Активность сессии" (count) + "System Health" (operational) — три разных concerns в одном ряду. Повтор ошибки v0.
3. **System Health снова в карточке** — должен быть chip в header рядом с `LIVE / MSK` (как operational status), не time-window.
4. **Block 3 — одиночная карточка с дельтой**, выпадает из grid. Либо full-width hero снизу, либо sparkline внутри hero "Текущего момента".
5. **"Активность сессии" vs "Среднее число запросов"** — концептуально пересекаются. Обе про сессии/запросы, разные гранулы. Нужно либо одно, либо строго разнести.
6. **Antifraud через "ещё одну цифру"** — слабый приём. Если `Среднее = 5000` и `Сегодня = 800K` → 160 tok/req (нормально). Если `Среднее = 50` и `Сегодня = 800K` → 16000 tok/req (аномалия). Цифра "среднее число" сама по себе аномалию не показывает — нужно **ratio**.

## 7. Рекомендация TL (текущий рабочий вариант)

**Главное: antifraud работает через ratio, не через count.**

Заменить «Среднее число запросов» на derived metric **Tokens / Request** — это и есть antifraud-сигнал, который нельзя раздуть. Увеличишь токены → растёт, уменьшишь запросы → растёт, выход из нормы виден за 1 сек без умственной арифметики.

**Сократить до 6 карточек в 2 ряда по 3:**

```
Row 1 (time-windows, единый язык):
  [ Текущий час ]   [ Сегодня ]   [ Рабочее окно ]

Row 2 (antifraud/ops, derived-метрики):
  [ Tokens ]        [ Requests ]   [ Tokens / Request ]
```

**System Health** → chip в header (`● OK · 94% · 2 events`), рядом с `LIVE / MSK`. Operational status, не time-window.

**Дельта к прогнозу** → либо wide-card full-width под row 2, либо sparkline-полоса в hero "Текущего часа". Не отдельная одинокая карточка.

**Активность сессии** — если это count активных сессий прямо сейчас → перенести в header рядом с LIVE (`● 3 active`). Если что-то другое → переименовать, иначе путается с `Requests`.
