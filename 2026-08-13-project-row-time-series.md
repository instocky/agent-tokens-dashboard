# Project-row time series (chevron + per-project inline panel)

**Status:** In Review
**Date:** 2026-08-13
**Scope:** `build_project_dashboard.py` + `project-dashboard.html`
**Out of scope:** `dashboard.html`, `session-dashboard.html`, остальные билдеры

## 1. Background

Текущий `project-dashboard.html` показывает только агрегаты за 5-недельное окно
(TOKENS, TOK/HOUR, DURATION, SESSION, LAST UPDATE). Истории потребления
токенов по проекту нет — нельзя увидеть, в какой день был пик, был ли
перерыв, когда проект реально «кодился».

Владелец TL, 2026-08-13: «добавить шеврончик, который будет открывать
панельку в которой временной ряд из столбиков затраченных токенов по дням
с начала разработки».

Один раунд обсуждения прошёл. Решение: **ступенчатое раскрытие** (дни →
клик по дню → 24h stream), per-project normalized Y, без подписей на
барах, inline `<tr>`, без sticky drawer.

## 2. Goals

- Шеврон на каждой строке таблицы открывает inline-зону **под строкой**
  с двухуровневой drill-down: дневной ряд → 24h stream для выбранного дня.
- Per-project normalized Y (100% = max за этот проект) — кросс-проектное
  сравнение остаётся задачей таблицы, чарт про это не врёт.
- Без подписей на барах — только tooltip при наведении. Это убирает
  визуальный шум и оставляет высоту как единственный кодирующий сигнал
  внутри проекта.
- 1-day проекты (55% датасета) рендерятся как single full-width bar +
  автоматически открытый 24h для этого дня.
- 0-day проекты (только сессии без `token_usage`) — без шеврона.

## 3. Non-goals

- НЕ per-session drill-down (это задача `session-dashboard.html`).
- НЕ кросс-проектное сравнение в чарте (для этого таблица + цифры).
- НЕ sticky bottom drawer — обсудили, отказались: теряет контекст «какой
  именно проект смотришь», экономия места не оправдана.
- НЕ persistent state через localStorage — после 60s meta-refresh ряд
  схлопывается. Открывать каждый раз заново — это нормальное поведение
  для glance-tool.
- НЕ вынос 24h-визуализации в shared helper — TL одобрил дубль
  (потом будет видно, нужно ли дедуплицировать).

## 4. Data

**Источник:** `local_runtime_token_usage` (per-turn, 21054 строк на
текущий БД-снапшот). Уже используется в `build_project_dashboard.py`
для total tokens per project.

**Join:** `local_runtime_token_usage.session_id →
local_runtime_sessions.record_json.workspaceDir → project_from_workspace
→ project slug` — тот же pipeline, что уже работает.

**Агрегации (новые):**

| Группировка                  | Что считаем                            | SQL шаблон (идентичен `build_dashboard.py::aggregate_by_hour`) |
| ---------------------------- | -------------------------------------- | -------------------------------------------------------------- |
| `(project, day)`             | SUM(input+output) per MSK day          | `date(ts/1000, 'unixepoch', '+3 hours')`                       |
| `(project, day, hour)`       | SUM(input+output) per MSK hour         | `date(...) + strftime('%H', ...)`                              |

**Окно:** то же, что в основной таблице — `start_ts_ms` из
`compute_window` (5 ISO-недель MSK) до `now_msk`. Для проектов < 5 недель
это фактически «с начала разработки», что и хотел владелец. Для проектов
старше 5 недель ряд обрезается — это согласуется со всей таблицей и
никого не удивляет.

**Per-project raw counts** (из диагностического прогона 2026-08-13):
29 проектов в БД, типичная длительность 1–6 дней, суммарно 21054 turn'а
(~700/проект в среднем). Агрегация GROUP BY недорогая, регенерация
HTML остаётся в пределах секунды.

## 5. UI

### 5.1 Шеврон (toggle)

- Слева от названия проекта в первой колонке, символ `▸`.
- По клику: `<tr class="detail-row" data-project="...">` под строкой
  получает класс `expanded`, контент внутри становится видимым
  (`display: table-row`).
- Повторный клик или клик на `▾` → `expanded` снимается, ряд
  схлопывается.
- `aria-expanded` синхронизируется для скринридеров.
- Без JS `<tr class="detail-row">` рендерится скрытым (`display: none`),
  чтобы не «светился» при отключённом JS.

### 5.2 Inline-зона (открытая панель)

```
┌──────────────────────────────────────────────────────────────┐
│ agent-tokens-dashboard                                       │
│ 6 дней · всего 215.2M · пик 13 авг (67.5M)                  │
│                                                              │
│ ▇▇▆▇▆▆  (дневной ряд, Y per-project, tooltip при hover)    │
│ 03 04 06 09 10 13                                           │
│                                                              │
│ ── 13 авг · 67.5M (кликни другой день для другой разбивки) ─│
│                                                              │
│ ▁▂▃▄▅▆▆▆▇▆▆▅▄▃▂▁ (24h stream для выбранного дня)          │
│ 00 01 02 ... 22 23                                           │
└──────────────────────────────────────────────────────────────┘
```

- **Заголовок:** `N дней · всего X · пик DD MMM (Y)`. Одна строка,
  моноширинно, справа как `meta` в шапке таблицы. Сразу отвечает на
  «стоит ли вообще смотреть дальше».
- **Дневной ряд:** ширина пропорциональна количеству дней в окне
  (одинаковая высота строк = `display: grid; grid-template-columns: repeat(N, 1fr)`).
  Per-project Y, без подписей. Tooltip: `DD MMM · 229.8M · 35%` (дата,
  абсолют через `format_tokens`, доля от total проекта).
- **Разделитель** (тонкая линия `var(--line)`): «DD MMM · total» —
  показывает, какой день сейчас выбран. Текст кликабельный
  (наследует тот же handler, что и бары).
- **24h stream для выбранного дня:** тот же компонент, что в
  `dashboard.html`, **inline продублирован** в `project-dashboard.html`
  с параметром `target_date = выбранный день`. CSS-классы совпадают
  (`.chart-shell--24h`, `.hours-24h`, `.hour-cell`, `.bar-24h.*`,
  `.hour-label`). Цвет тот же `#216e39`.
- **1-day проект:** дневной ряд = один full-width bar с подписью
  «единственный день активности», 24h stream рендерится сразу
  автоматически (других дней кликать не надо).
- **Empty state:** не бывает, потому что шеврон не рендерится для
  0-day проектов. Если БД настолько свежая, что у проекта вообще нет
  token_usage — ряд без шеврона, как сейчас.

### 5.3 Взаимодействие

- Клик по бару в дневном ряду → меняет выбранный день, 24h stream
  перерисовывается на этот день. Никаких анимаций, мгновенная замена
  innerHTML. Текущий выбранный день визуально выделен outline
  (как `.bar.selected`).
- Hover на баре → tooltip + лёгкий `brightness(1.18)` (тот же эффект,
  что на `.bar-24h:hover`).
- Hover на 24h баре → стандартный `title=` tooltip («HH:00–HH:59: X.XK»).
- Клик по `▸/▾` шеврона — toggle. Без анимаций, мгновенно.

## 6. Edge cases

| Случай                       | Поведение                                               |
| ---------------------------- | ------------------------------------------------------- |
| 0-day проект (нет token_usage в окне) | Без шеврона, как сейчас без чисел.             |
| 1-day проект                 | Один full-width bar, 24h раскрыт сразу.                 |
| max/min day ratio ≤ 5x       | Линейная шкала высоты бара.                             |
| max/min day ratio > 5x       | Логарифмическая шкала (`height = log(1+v)/log(1+max)`). |
| Будущие дни в окне           | Не бывает — окно обрезано по `now_msk`.                |
| День с value=0               | Рендерится как empty bar (2px floor, `var(--muted)`).   |
| Project is_active            | Не влияет на чарт, оставляем существующий бейдж.        |
| meta-refresh (60s)           | Inline-зоны схлопываются (controlled state, не persistent). |

## 7. Acceptance criteria

1. **Build:** `python build_project_dashboard.py` отрабатывает за < 2 сек
   (с новыми агрегациями, без warning'ов в stderr).
2. **Chevron present:** на каждой строке с ≥ 1 днём token_usage есть
   кликабельный `▸` перед названием проекта. На 0-day строках шеврона нет.
3. **Click toggles:** клик по шеврону открывает inline-зону, повторный
   клик закрывает. Состояние `aria-expanded` соответствует DOM.
4. **Daily chart:** per-project normalized Y. Tooltip формата
   `DD MMM · X.XM · NN%`. Лог-шкала включается автоматически при
   ratio > 5x.
5. **24h switch:** клик по бару в дневном ряду меняет 24h stream на
   этот день. Визуально выбранный день отмечен.
6. **Header line:** `N дней · всего X · пик DD MMM (Y)` в одну строку
   над дневным рядом. На 1-day проекте — «1 день · всего X · DD MMM (Y)».
7. **1-day case:** один full-width bar с подписью «единственный день
   активности», 24h stream рендерится сразу. Кликать нечего, но layout
   валидный.
8. **No persistence:** после `meta http-equiv="refresh"` (60s) inline-зоны
   схлопнуты, localStorage не используется.
9. **No regression:** таблица продолжает сортироваться кликом по
   колонкам (existing JS, контракт не трогаем).
10. **Self-contained:** `project-dashboard.html` работает
    file:// — никаких внешних JSON, iframe, шрифтов с CDN.

## 12. Follow-up: day-grid (GitHub-style heatmap) — 2026-08-20

Замечание TL, 2026-08-20: визуальная консистентность дневного ряда
плавала в зависимости от N дней в проекте (1 / 7 / 18). 1-day проект
выглядел «сиротливо» (один full-width бар в 30%-колонке), 18-day
проект — «решёткой с дырами» (14 из 18 пустых баров).

Решение: **заменить `.day-bars` + `.day-labels` на `.day-grid`** —
GitHub-contributions-style heatmap:

- 7 строк (Пн..Вс) × N недель.
- Окно: 1-е число предыдущего месяца .. today MSK (inclusive),
  обёрнутое в полные недели Пн..Вск. Out-of-window ячейки (padding
  начала + будущие дни текущей недели) — transparent, некликабельные.
- 4 уровня интенсивности зелёного (`var(--accent-2)` = #10b981) для
  дней с данными: 0-25% / 25-50% / 50-75% / 75-100% от max_value
  внутри проекта. Лог-шкала тут НЕ применяется (bucket'и работают
  только в линейной шкале).
- Пустые дни в окне — `rgba(255,255,255,0.06)` (pale, как раньше).
- Сегодня — точка в правом верхнем углу ячейки.
- Выбранный день — `outline: 1.5px solid rgba(255,255,255,0.85)`.
- Шапка: месяц (МХХ) на колонку, Пн/Ср/Пт слева, угол пустой.

**Лейаут:**

- `.detail-inner--side-by-side` теперь применяется ВСЕГДА (без порога
  N≤7) — грид фиксированной ширины (180px), не зависит от N. Stacked
  варианта больше нет.
- `.detail-inner` columns: `180px 1fr` (раньше `30% 1fr`) — грид
  слева, 24h шире справа.
- `.day-separator` скрыт в side-by-side (24h прижат к гриду без
  разделителя).

**Acceptance дополнение к §7:**

- 1-day проект: грид рендерится как обычно (1 цветная ячейка в окне
  ~50 ячеек), 24h рендерится сразу, выбранная ячейка = сегодня = пик.
- 18-day проект: ~4 цветных ячейки в окне ~50, остальные pale, 24h
  широкий.
- Hint `↓ клик по дню → 24h` показывается для ВСЕХ проектов (раньше
  прятался для 1-day).
- `data-tokens="0"` ячейки не имеют `role="button"`, не реагируют
  на hover/click; `cursor: default`.
